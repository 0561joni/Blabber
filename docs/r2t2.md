# R2T2 live shortcut dictation

Implemented for Apple Silicon and macOS 14+, using audio.cpp, Metal and the pinned
Q8_0 model. The integration is **available in normal builds as an opt-in experimental
model** for direct testing in the app. Human accuracy, acoustic latency and
interactive packaged-app acceptance remain outstanding. Synthetic/native checks
below passed; they do not replace those acceptance checks. Existing selections and
defaults are unchanged.

## Behavior and configuration

R2T2 supports shortcut dictation only. Selecting it in Settings → Models enables
live preview automatically. Source language may be Auto, German or English; use
Auto for mixed speech. GPU acceleration must be enabled. Other in-app Dictate and
file transcription selections retain their existing engines. R2T2 cannot enter a
batch-ASR path, and a missing or corrupt model produces a setup error, never a
fallback to another engine.

The passive, non-focusable, click-through overlay uses a 480 × 64 logical-pixel
window with an output-language badge, microphone indicator and single scrolling
line. New text scrolls to the end; microphone updates do not move it. Reduced
motion disables animated scrolling. Preparing, waiting, catching up, finishing
and translating are distinguished; more than two seconds of decoder backlog is
shown as catching up. Original-language text remains visible during translation.

Stopping drains capture and its final resampler tail, explicitly flushes the
native decoder, validates complete sample coverage and the committed prefix,
applies the snapshotted vocabulary, optionally translates, saves history when
enabled, and performs the existing single paste/copy flow. At five minutes the
capture limit finishes normally and the overlay explains the limit. The old
90-second recording watchdog does not apply to a live R2T2 session.

Failed streaming retains the current recording and offers **Retry transcription**
in Dictate. Retry returns text for the user to copy and never pastes into the old
application. Reset, shutdown or a newer session prevents late text, history or
paste callbacks from taking ownership.

## Runtime and data flow

The source/model pins, exact 2,477,512,064-byte size, SHA-256 values and terms are in
[`workers/r2t2/manifest.json`](../workers/r2t2/manifest.json). Source archives are
verified before patching. The build cache is keyed by upstream revision, patch and
rolling-ledger checksums. Model installation uses the existing resumable verified
downloader; the parent verifies the complete weights before a cold load and checks
size/mtime and worker health before warm reuse. Q4/Q5 packages are incompatible.

The microphone callback retains capture samples. A separate thread normalizes
them continuously to 16 kHz mono with the same stateful normalizer used for final
audio. Raw capture is capped at five minutes, and complete normalized audio remains
available while the model loads or waits for the queue. Inference advances exact
acknowledged sample cursors and submits one configured chunk per native API call.

Protocol v1 is bounded newline-delimited JSON over child stdin/stdout, with
`start`, `audio`, `finish`, `cancel`, `reset` and readiness/progress/final/error
responses. Every request and response has a session and monotonic sequence. The
parent rejects malformed, stale, duplicate, incomplete and prefix-rewriting
responses. Blocking writes and reads run on separate threads so cancellation and
deadlines remain responsive. Cancellation kills and reaps the process group;
a cancel frame alone cannot interrupt synchronous native inference.

The native patch uses a 16-second audio window advancing eight seconds, with
sample-indexed emission entries and separately retained complete text. It validates
exact prefix agreement and flushes withheld words even at an exact chunk boundary.
It does not cut sentences or use fuzzy deduplication. Emission positions are not
word timestamps, so successful bookkeeping tests alone cannot prove recognition
at a rolling seam. Native diarization and word timestamps are not advertised.

Queue admission is requested at capture start with dictation priority. An active
file job remains uninterrupted. The shared queue serializes warm reuse and
eviction: no other model can allocate until the previous helper has been reaped.
An Original-mode completion may cache the helper for 60 seconds without retaining
the processing permit. Translation reaps it before loading its own model. Other
workloads, settings/model changes, reset, shutdown and macOS memory-pressure
notifications evict the idle helper. Cache epochs prevent an already-invalidated
session from caching its worker later.

Capture must continue delivering samples (five-second stall check). Loading has
a 90-second deadline, individual native exchanges have progress deadlines, and
post-stop ASR has a 90-second budget starting after queue admission if it was still
waiting. Queue waiting itself is not a failed model execution. Shutdown counts the
inference thread and any undelivered completion as active work until the child
has exited or entered the queue-owned idle cache. Production diagnostics
contain timing, queue lag, peak RSS and error codes, without transcript or audio.

Overlay snapshots carry session ID, live text, streaming state, lag and revision.
Session-checked microphone/text updates cannot revive an old session. Rendering
is coalesced to at most ten snapshots per second; main-thread window updates and
frontend subscriptions reject stale revisions.

## Measurements on this Mac

Measured 2026-09-22 on Apple M3 Pro, 12 CPU cores, 18 GB RAM, macOS 27. These are
offline synthetic speech probes generated with macOS Anna and Samantha voices,
not a human accuracy evaluation. Fixtures deliberately cross rolling boundaries.
Reports identify the tested binary, model and audio by checksum. Earlier long-run
probes predate the final protocol/diagnostic hardening; the inference and rolling
configuration is the same. Runtime source patches and weights are local.

Candidate configuration: **640 ms chunks, five-token rollback**, internal only.
The four requested cadences and both rollback settings were evaluated on the
79.6-second German fixture. At 320 ms, compute exceeded incoming audio duration
(real-time factor 1.14–1.28). At 640 ms it was 0.57–0.69. Larger chunks were faster
but offer less frequent updates. Five-token rollback retained the tested number
more reliably than one-token rollback in the exploratory comparison. This choice
is provisional until human latency and accuracy acceptance.

| Five-minute fixture | Chunk / rollback | Stream + final compute | Final native flush | Real-time factor |
| --- | --- | ---: | ---: | ---: |
| German | 640 ms / 5 | 220.80 s | 0.42 s | 0.736 |
| English | 640 ms / 5 | 232.81 s | 0.43 s | 0.776 |
| Mixed, automatic language | 640 ms / 5 | 236.89 s | 0.44 s | 0.790 |
| English, exact final chunk boundary | 2,000 ms / 5 | 95.88 s | 0.43 s | 0.320 |

Those runs fed audio as fast as possible. They demonstrate native throughput and
complete protocol finalization across five minutes, **not** end-to-end word delay
or finish-to-paste latency. Observed warm-cache cold-process model loads were about
2.2–2.6 seconds, with peak child RSS about 5.14 GB (4.79 GiB). Full app cold start,
weight checksum time and filesystem-cold loading are separate costs.

A subsequent **paced packaged-helper** five-minute mixed-language probe retained
loading backlog, produced exactly the same final text as the unpaced run, and
returned its final result 0.40 seconds after simulated capture ended. Its first
visible committed text arrived 2.81 seconds after helper launch, including a
2.10-second load. Per-chunk acknowledgment lag had median 0.49 s, p95 0.58 s and
maximum 1.67 s; these are processing acknowledgments, **not acoustic word delays**.
Peak RSS was 5.14 GB. An app build ran concurrently during roughly the first
40 seconds, so this is a backlog/continuity stress probe, not isolated performance
acceptance. Its clock excludes the prior checksum check and does not exercise a
microphone, overlay or paste.

rating or as satisfying the per-language human release gate.

## Validation and development

Automated checks completed: 174 Rust tests, 101 frontend tests, five native
protocol tests and native rolling-ledger tests at all four cadences. Coverage
includes packet-boundary resampling equivalence, final samples, capped capture,
queue priority/non-preemption, idle eviction and reuse, invalidated cache epochs,
worker timeout/reaping, discarded-completion ordering, cancellation immediately
before paste/retry, protocol ordering, Unicode,
overlay revision ordering, text retention, reduced motion and existing clipboard,
translation/history and cancellation regressions. The normal suite leaves eight
environment-dependent Rust tests ignored; the real R2T2 adapter test is explicitly
run with the pinned model and Metal access. That Rust adapter check passed against
the packaged helper for both a cold session and warm reuse in the same process.

The Apple Silicon app bundle builds with the helper and all notices. The helper's
signature verifies and it depends only on system frameworks/libraries. Without
`APPLE_SIGNING_IDENTITY` the build uses an ad-hoc development signature; this does
not constitute Developer ID notarization or an interactive packaged-app pass.

```sh
npm run build:r2t2
python3 -m unittest discover -s workers/r2t2 -p test_protocol.py
npm test
cd src-tauri
cargo test --lib
cargo test --lib r2t2::tests::real_native_adapter_completes_and_reuses_a_warm_session -- --ignored
```

See the [worker README](../workers/r2t2/README.md) for generating fixtures and
running benchmarks. Build the normal app and installer with `npm run tauri -- build`.
In Settings → Models, download **R2T2 · Experimental**, enable GPU acceleration,
and select it for **Shortcut dictation**. No debug build or environment override is
required. Start with Original output and Auto source language to test mixed German
and English. Switch the shortcut model back at any time to restore the previous
behavior. For development builds, setting `CARGO_PROFILE_DEV_OPT_LEVEL=2` avoids
very slow unoptimized SHA-256 verification of the 2.48 GB weights.

## Remaining acceptance checks

- Record at least 20 human clips per language, plus five-minute German, English
  and mixed speech. Include names, numbers, vocabulary, umlauts, repetitions and
  identifiable words immediately before and after rolling boundaries.
- Compare each language against the existing shortcut model using consistent
  normalization: WER must be no more than two percentage points worse. Review
  seams explicitly for omissions/repetitions and final withheld words.
- Annotate acoustic word times and measure median visible-word delay ≤1 s,
  p95 ≤2 s, faster-than-real-time processing and Original-mode p95 finish-to-paste
  ≤2 s. Report cold starts and translation separately. Experimental speed may be
  slower, but correctness and the 90-second post-stop budget remain mandatory.
- In the packaged app exercise real microphone packets, queue contention, rapid
  release/restart, five-minute auto-stop, cancel/reset/quit during loading,
  inference, translation and immediately before paste; verify memory stays
  bounded and no stale output is inserted.
- Verify warm reuse, 60-second expiry, memory-pressure eviction, model switches,
  translation memory handoff, damaged downloads and explicit recovery. Check
  Original/French/Argentinian Spanish, history on/off, focus preservation,
  clipboard restoration, multiple monitors, Retina scaling and reduced motion.
- Repeat packaging under the release signing identity and distribution workflow.
  Publish human/M3 Pro measurements before removing the experimental designation.
  Rollback is immediate by selecting the previous shortcut model.
